# Abstract interpretation for GraalVM Native Image

<ProjectMeta slug="/projects/abstract-interpretation-graalvm" />

A framework for abstract interpretation that works directly on Native Image's
Sea-of-Nodes intermediate representation, developed at FI MUNI together with
Oracle Labs. The analysis is not a pass over a separate representation: it runs on
the graph the compiler already has, and the abstract facts it computes are
attached to the IR nodes themselves.

The work lives in the `substratevm/ai` area of
[github.com/S3MU1L/graal](https://github.com/S3MU1L/graal).

## Abstract domains

The domains are extensible — adding one means implementing its lattice
operations rather than touching the fixpoint engine. Implemented so far:

- `interval` — value ranges;
- `sign` — sign abstraction;
- a `pentagon`-style domain, combining interval information with symbolic
  relations between variables.

## Fixpoint iteration

Analysis is a worklist-based fixpoint computation with widening. A node is
re-evaluated when one of its inputs changes; widening keeps iteration over
cyclic data flow — a loop, which in Sea-of-Nodes form is a `φ` node fed by a back
edge — from ascending an infinite chain.

## Pipeline integration

The analysis runs inside the Native Image compilation pipeline rather than as an
offline tool. That is what makes its results usable by later phases, and also what
makes compile time a first-class constraint.

Alongside it there is infrastructure to propagate and inspect abstract facts per
IR node and per program location. That is needed both by consumers of the analysis
and for debugging the analysis itself, where the question is usually "what did the
analysis believe at this node, and why".

## Context-sensitive interprocedural analysis

A significant part of the work is the investigation of context-sensitive
interprocedural analysis: how much distinguishing calling contexts buys in
precision, and what it costs in compile time. That trade-off is the reason the
domains and the fixpoint engine are kept separable — the same domain can be run
under different amounts of context sensitivity.
