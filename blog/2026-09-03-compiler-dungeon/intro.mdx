# Compiler Dungeon ️⛽

import PipelineExplorer from '@site/src/components/PipelineExplorer';

This is an educational compiler built to demonstrate the core ideas in compiler theory. It targets a
small language — Kerosene — expressive enough to write real programs with, while staying small enough
that every stage of the pipeline fits in your head at once. The source is on
[github](https://github.com/samuel-malec/compiler-dungeon), and the language itself is documented
[here](https://github.com/samuel-malec/compiler-dungeon/blob/main/docs/language.md).

I'll be writing more detailed posts on individual parts of this pipeline over time. This post is the
front door: an interactive compiler embedded directly in the page, so you can see how a program
actually moves through each stage before reading about any of them in depth.

## How the pipeline works

### 1. Tokens & parsing

The lexer turns source text into a flat stream of tokens, and a Pratt parser assembles those tokens
into an AST that mirrors the language's grammar directly — no intermediate representation yet, just
the program's syntax as a tree.

### 2. HIR

The AST gets type-checked and desugared into HIR: every expression now carries the type the checker
resolved for it, but control flow (`if`, `while`, `loop`) is still structural, not yet expressed as
jumps between blocks.

### 3. IR and SSA

HIR lowers into a flat instruction sequence with explicit labels and branches, which a separate CFG
pass then splits into basic blocks. `mem2reg` promotes local variables out of memory and into SSA
form, where every value is defined exactly once and merge points get explicit phi nodes.

### 4. SCCP

Sparse Conditional Constant Propagation walks the SSA form once, tracking which values are provably
constant and which branches are provably one-sided. Where it can prove a condition, it collapses the
branch and deletes the code that can no longer run.

### 5. DCE

Dead Code Elimination removes instructions whose results are never used and which have no side
effects. It's a natural pairing with SCCP: folding a branch or a constant is exactly what turns
previously-live computations into dead ones.

## Implementation

The compiler itself is plain C++20 with no dependencies, built as both a native CLI and a WebAssembly
module (the one running the widget above) via Emscripten. The full source, including the SCCP and
CFG-simplification passes described above, is on
[github](https://github.com/samuel-malec/compiler-dungeon).
